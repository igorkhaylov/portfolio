# Контент сайта: что где хранится

Весь текст на сайте — строки в базе, ничего не зашито в шаблоны. Этот документ — карта:
какая информация о владельце в какую модель попадает и как её заполнять.

Заполнять можно двумя способами:

1. **Админка** — `/ru/admin/`, обычный путь для точечных правок.
2. **`seed_portfolio`** — команда с исходными данными в коде
   (`backend/apps/portfolio/management/commands/seed_portfolio.py`). Идемпотентна:
   правишь словари в файле, запускаешь ещё раз — записи обновляются на месте.

```bash
make dev bash
python manage.py seed_portfolio
```

Крупные добавления (новый блок опыта, пачка навыков) удобнее вносить в `seed_portfolio`
— они попадают в git и переживают пересоздание базы. Разовые правки — в админке.

## Двуязычность

Переводимые поля продублированы суффиксами: `position_ru` / `position_en`. В админке это
вкладки языков. Язык по умолчанию — русский; пустое английское поле показывает русский
текст (`MODELTRANSLATION_FALLBACK_LANGUAGES`), так что сайт не ломается, пока перевод не
дописан.

В коде (seed, миграции данных) **всегда пиши суффикс явно** — `position_ru=...`. Без
суффикса значение уйдёт только в тот язык, который активен в момент выполнения.

Полный список переводимых полей — `backend/apps/portfolio/translation.py`.

## Модели

### Profile — кто ты

Одна активная запись, из неё рендерятся сайдбар, hero и блок «Обо мне».

| Поле | Что писать |
|---|---|
| `full_name` | Имя и фамилия. Не переводится |
| `headline` | Роли через запятую — они по очереди печатаются в hero: `Python-разработчик, Backend-разработчик` |
| `role` | Одна строка-заголовок в блоке About |
| `summary` | 2-3 предложения под заголовком «Обо мне» |
| `bio` | Более длинный текст, идёт в блок «Резюме → Кратко» |
| `location`, `email`, `phone`, `birth_date` | Контакты |
| `career_started_at` | Год начала карьеры — из него считается стаж («7 лет») |
| `is_available_for_hire` | Показывает «Фриланс: возможен» |
| `avatar`, `hero_image` | Фото и фон hero. Варианты размеров создаются автоматически |
| `resume_file` | PDF резюме — появляется кнопка «Скачать CV» |
| `meta_description`, `meta_keywords` | SEO и превью в соцсетях |
| `is_active` | Сайт рендерит первый активный профиль |

`SocialLink` (инлайн внутри Profile) — ссылки-иконки в сайдбаре. `icon` — класс
[boxicons](https://boxicons.com/), например `bxl-telegram`, `bxl-github`.

### Experience — опыт работы

Одна запись = одно место работы или период фриланса.

- `position`, `company`, `location`, `company_url`
- `started_at` / `finished_at`; `is_current` — для текущего места (тогда конец не нужен,
  период отрисуется как «2020 — настоящее время»)
- `description` — абзац текста
- `highlights` — **по одному пункту на строку**, отрисуется маркированным списком
- `rank` — порядок вывода, меньше значение = выше. Шаг 10, чтобы можно было вставлять
  между

### Education / Course — образование и курсы

Та же логика периодов и `highlights`.

- `Education`: формальное образование — `institution`, `degree`, `speciality`
- `Course`: самообразование и сертификаты — `title`, `provider`, `url` (ссылка на
  сертификат)

### SkillGroup / Skill — стек

`SkillGroup` — колонка («Backend», «Инфраструктура», «Frontend»). `Skill` — технология:

- `level` (0-100) — ширина полоски прогресса
- `icon` — класс boxicons, например `bxl-python`
- `is_featured` — вынести навык в блок About

Эти же `Skill` служат тегами стека для проектов, так что дублировать список технологий не
нужно.

### ProjectCategory / Project / ProjectImage — портфолио

`ProjectCategory` — кнопки фильтра над сеткой проектов. Категория без опубликованных
проектов в фильтре не показывается.

`Project`:

| Поле | Что писать |
|---|---|
| `title`, `slug` | Slug попадает в URL `/projects/<slug>/` |
| `summary` | Одна строка под карточкой в сетке |
| `description` | Полное описание на странице проекта |
| `highlights` | Что конкретно сделано — по пункту на строку |
| `role`, `client` | Твоя роль и заказчик |
| `cover` | Обложка карточки; отдаётся в трёх размерах |
| `project_url`, `repository_url` | Ссылки на сайт и на код |
| `skills` | Стек — выбирается из `Skill` |
| `released_at` | Дата запуска |
| `is_featured`, `is_published`, `rank` | Витрина, публикация, порядок |

`ProjectImage` — галерея на странице проекта (инлайн внутри Project).

### ContactMessage — входящие

Заполняется формой на сайте, руками не создаётся. У формы есть honeypot-поле и минимальная
длина сообщения. После сохранения Celery шлёт письмо на `DJANGO_CONTACT_NOTIFY_EMAIL`
(или на `Profile.email`, если переменная пустая). Если брокер недоступен — сообщение всё
равно сохранится, в лог уйдёт предупреждение.

## Как добавить проект

Базовый список проектов (тексты, стек, категории) живёт в `seed_portfolio` — правки
вносить там и перезапускать команду. Обложки и скриншоты команда не трогает, они
загружаются через админку. Разовый проект можно завести и целиком в админке:

1. Админка → **Проекты → Добавить**.
2. Заполнить `title` (ru и en), slug сгенерируется из русского названия.
3. Выбрать категорию, загрузить обложку, добавить стек во вкладке «Стек».
4. Добавить скриншоты в инлайне «Изображения проекта».
5. `is_published` = да.

Проект сразу появляется в сетке, в фильтре по категории и в `sitemap.xml`.

## Чего в моделях намеренно нет

- **Отзывы и услуги** — блоки из исходного шаблона, которые были закомментированы. Если
  понадобятся, добавляются как отдельные модели по тому же образцу (`BaseModel` + `rank` +
  `is_published`).
- **Блог** — отдельная сущность; при необходимости заводится своим приложением, а не
  расширением `Project`.
